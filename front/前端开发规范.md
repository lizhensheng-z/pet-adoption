# 宠物领养平台 - 前端开发规范

## 1. 项目概述

### 1.1 技术栈
- **框架**: Vue 3 (Composition API)
- **构建工具**: Vite
- **路由**: Vue Router 4
- **状态管理**: Pinia
- **UI组件库**: Element Plus

## 2. API 接口规范

### 2.1 请求封装
所有 API 请求通过 `src/api/request.js` 统一处理：

```javascript
import http from '@/api/request.js'

// GET 请求
http.get('/url', params, config)

// POST 请求  
http.post('/url', data, config)

// PUT 请求
http.put('/url', data, config)

// DELETE 请求
http.delete('/url', params, config)

// 文件上传
http.upload('/url', formData, config)
```

### 2.2 API 模块划分
按业务模块在 `src/api/modules/` 下创建对应文件：
- `auth.js` - 认证相关（登录、注册、登出、刷新Token）
- `pet.js` - 宠物相关
- `org.js` - 机构相关
- `admin.js` - 管理端相关

### 2.3 响应格式规范
后端统一响应格式：
```json
{
  "code": 10000,
  "message": "操作成功",
  "data": { ... },
  "timestamp": "2026-02-13 11:57:26"
}
```

成功码定义 (`src/api/types.js`)：
```javascript
export const RESPONSE_CODES = {
  SUCCESS: 10000,          // 操作成功
  AUTH_FAILED: 1001,       // 认证失败
  PERMISSION_DENIED: 1002, // 权限不足
  VALIDATION_FAILED: 1003,  // 参数验证失败
  NOT_FOUND: 1004,         // 资源不存在
  BUSINESS_CONFLICT: 1005, // 业务冲突
  RATE_LIMITED: 1006,      // 请求限流
  SERVER_ERROR: 1007       // 服务器错误
}
```

### 2.4 Token 管理
- Access Token: 存放在 `localStorage` 键名 `pet_adoption_access_token`
- Refresh Token: 存放在 `localStorage` 键名 `pet_adoption_refresh_token`
- 通过 `src/utils/auth.js` 工具函数统一管理

- 机构端: `/org/` 开头

## 4. 状态管理规范

### 4.1 Store 划分
- `auth.js` - 用户认证状态、Token、权限
- `user.js` - 用户个人信息、偏好设置
- `app.js` - 全局应用状态（主题、侧边栏、位置信息）

### 4.2 State 定义规范
```javascript
state: () => ({
  token: getAccessToken(),
  refreshToken: getRefreshToken(),
  user: null,
  permissions: [],
  isLoading: false
})
```

### 4.3 Getter 规范
```javascript
getters: {
  isLoggedIn: (state) => !!state.token,
  userRole: (state) => state.user?.role || 'USER',
  hasPermission: (state) => (permission) => {
    return state.permissions.includes(permission)
  }
}
```

// 方法

  emit('click', data.value)

  // 初始化逻辑

## 8. Git 提交规范

### 8.1 提交信息格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

### 8.2 Type 类型
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 样式调整
- `refactor`: 代码重构
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建/工具

### 8.3 示例
```
feat(auth): 添加登录页面

- 新增登录表单组件
- 集成后端登录API
- 添加Token管理

Closes #123
```

## 9. 开发流程规范

### 9.1 新增页面步骤
1. 在 `views/` 对应目录下创建页面组件
2. 在 `router/` 对应路由文件中配置路由
3. 如需API，在 `api/modules/` 下添加接口
4. 如需状态，在 `stores/` 下添加或更新Store

### 9.2 新增API步骤
1. 在 `api/modules/` 对应模块文件中添加接口方法
2. 使用统一的请求封装方法

### 9.3 新增组件步骤
1. 通用组件放入 `components/common/`
2. 布局组件放入 `components/layout/`
3. 组件必须使用 `<script setup>` 语法

---

## 10. 注意事项

1. **禁止直接操作 localStorage**，统一使用 `src/utils/storage.js`
2. **Token 存储**必须通过 `src/utils/auth.js` 工具函数
3. **所有页面必须使用 `AppLayout` 布局组件**
4. **页面标题必须使用 `PageHeader` 组件**
5. **所有 API 请求必须使用统一的请求封装**
6. **响应码统一使用 `src/api/types.js` 中定义的常量**
7. **样式变量必须使用 SCSS 变量，禁止硬编码颜色值**
