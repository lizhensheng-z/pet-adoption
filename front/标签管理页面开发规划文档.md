# 标签管理页面开发规划文档

> 本文档基于标签字典表(tag)及宠物-标签关联表(pet_tag)制定，提供标签管理功能的完整前后端接口规范，确保前后端按照统一标准开发。

---

## 1. 数据库表结构分析

### 1.1 标签字典表(tag)

```sql
CREATE TABLE tag (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    name VARCHAR(64) NOT NULL COMMENT '标签名称',
    tag_type VARCHAR(32) NOT NULL COMMENT '标签类型：SPECIES/PERSONALITY/HEALTH/FEATURE',
    enabled TINYINT NOT NULL DEFAULT 1 COMMENT '是否启用：0否1是',
    deleted TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0否1是',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    UNIQUE KEY uk_type_name(tag_type, name),
    INDEX idx_tag_type(tag_type) COMMENT '标签类型索引'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='标签字典表';
```

### 1.2 字段说明

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| id | BIGINT | 标签唯一标识 | 1 |
| name | VARCHAR(64) | 标签名称 | "活泼", "已接种疫苗" |
| tag_type | VARCHAR(32) | 标签类型 | SPECIES(物种)/PERSONALITY(性格)/HEALTH(健康)/FEATURE(特征) |
| enabled | TINYINT | 是否启用 | 0(禁用), 1(启用) |
| deleted | TINYINT | 逻辑删除 | 0(未删), 1(已删) |
| create_time | DATETIME | 创建时间 | 2024-02-16 10:00:00 |

## 3. 后端接口规范

### 3.1 管理端接口

#### 3.1.1 获取标签列表（分页）

**请求方式**: `GET`  
**请求路径**: `/api/admin/tags`  
**请求参数**: `pageNo`, `pageSize`, `name`, `tagType`, `enabled`

**响应示例**:
```json
{
  "code": 10000,
  "data": {
    "list": [
      {
        "id": 1,
        "name": "活泼",
        "tagType": "PERSONALITY",
        "tagTypeText": "性格特征",
        "enabled": 1,
        "createTime": "2024-02-16 10:00:00"
      }
    ],
    "total": 50
  }
}
```

#### 3.1.2 创建标签

**请求方式**: `POST`  
**请求路径**: `/api/admin/tags`  
**请求体**:
```json
{
  "name": "亲人",
  "tagType": "PERSONALITY",
  "enabled": 1
}
```

#### 3.1.3 更新标签

**请求方式**: `PUT`  
**请求路径**: `/api/admin/tags/{id}`

#### 3.1.4 删除标签（软删除）

**请求方式**: `DELETE`  
**请求路径**: `/api/admin/tags/{id}`

#### 3.1.5 切换启用状态

**请求方式**: `PATCH`  
**请求路径**: `/api/admin/tags/{id}/status`

## 4. 前端实现规范

### 4.1 API模块定义

**文件路径**: `src/api/modules/admin.js`

```javascript
export const tagApi = {
  // 获取标签列表
  getTagList: (params) => http.get('/admin/tags', params),
  // 创建标签
  createTag: (data) => http.post('/admin/tags', data),
  // 更新标签
  updateTag: (id, data) => http.put(`/admin/tags/${id}`, data),
  // 删除标签
  deleteTag: (id) => http.delete(`/admin/tags/${id}`),
  // 切换状态
  toggleTagStatus: (id, enabled) => 
    http.patch(`/admin/tags/${id}/status`, { enabled })
}
```

### 4.2 状态管理 (Pinia)

**文件路径**: `src/stores/tag.js`

```javascript
import { defineStore } from 'pinia'
import { tagApi } from '@/api/modules/admin.js'

export const useTagStore = defineStore('tag', {
  state: () => ({
    tagList: [],
    total: 0,
    loading: false
  }),
  actions: {
    async fetchTagList(params) {
      this.loading = true
      const res = await tagApi.getTagList(params)
      if (res.code === 10000) {
        this.tagList = res.data.list
        this.total = res.data.total
      }
      this.loading = false
    }
  }
})
```

## 6. 开发注意事项

1. **唯一性校验**: 数据库设有 `uk_type_name` 唯一索引。新增/编辑时，后端需捕获异常并返回友好提示（如：“该类型下已存在同名标签”）。
2. **类型常量**: 前端建议维护一个 `TagType` 对象，映射英文 Key 到中文名称，确保列表展示和下拉框一致。
3. **关联删除**: 删除标签前，后端需检查 `pet_tag` 表。如果该标签已被大量宠物引用，建议提示用户或采用静默逻辑删除（`pet_tag` 相应记录也应标记删除）。
4. **缓存**: 标签作为字典数据，变动频率低，用户端获取标签列表接口可设置较长时间缓存。
